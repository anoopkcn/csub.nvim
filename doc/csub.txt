INTRODUCTION                                                       *csub-intro*

csub lets you edit the current quickfix or location list in a scratch buffer
and write the changes back to the original files. It shows a metadata column
(file|line:col) beside each entry to keep context while editing, and marks
edited rows with a `~` sign in the sign column.

Different modes allow csub to behave appropriately based on the list source:
- "replace" mode: Edit text to replace lines in source files (grep, make)
- "buffers" mode: Delete lines to close buffers (buffer pickers)

`:Csub` works on whichever list (quickfix or location) you invoke it from.
A range scopes editing to a slice of the list — see |csub-scope|.

==============================================================================
SETUP                                                              *csub-setup*

The `:Csub` command, the `quickfixtextfunc`, the augroup, and the highlight
groups are registered automatically at Neovim startup by `plugin/csub.lua`.
However, csub is OPT-IN: with no `setup()` call, `:Csub` is disabled for
every list (it prints a message and does nothing). To enable it, either set
a `default_mode` or list the titles you want handled via `handlers`.

Minimal opt-in (every list gets "replace" mode):
>lua
    require("csub").setup({ default_mode = "replace" })
<

Per-list-title configuration:
>lua
    require("csub").setup({
        handlers = {
            { match = "FuzzyBuffers", mode = "buffers" },
            { match = "Grep",         mode = "replace" },
            { match = "vimgrep",      mode = "replace" },
            { match = "Diagnostics",  mode = nil       }, -- disable csub
        },
        default_mode = nil, -- unmatched lists stay disabled
    })
<

`setup()` only merges your options into the module-scoped config table; it
has no other side effects. The same handler list is checked for both
quickfix and location list titles.

Tip: to find the title a command produces, run the command and inspect
`vim.fn.getqflist({ title = 1 }).title` (or `getloclist(0, { title = 1 })`
for a loclist). Match against any unique substring of that title.

==============================================================================
USAGE                                                              *csub-usage*

- Populate a quickfix list (`:make`, `:grep`, `vim.diagnostic.setqflist()`, a
  file picker) or a location list (`:lvimgrep`, `:lgrep`, ...).
- Open the list window (`:copen` or `:lopen`) and run `:Csub` from inside it
  to open the editable buffer in place.
- Optionally scope to a slice with a range: `:5,10Csub` or `:'<,'>Csub`.
- Edit the lines directly. Edited rows get a `~` sign in the sign column.
  Deleting a line removes that entry. Attempts to add lines are reverted
  with a warning.
- Run `:Csub` again to jump back to the list window while keeping unsaved
  edits in the csub buffer.
- Write (`:w`) to apply changes back to the underlying files / list; the
  list window is shown again after writing.

==============================================================================
EXAMPLES                                                        *csub-examples*

Find and replace across files (uses "replace" mode):
>vim
    :grep -rn "old_name" .
    :copen
    :Csub
    " edit lines, then:
    :w
<

Find and replace within a location list:
>vim
    :lvimgrep /old_name/ **/*.lua
    :lopen
    :Csub
    " edit lines, then:
    :w
<

Edit only a slice of a long quickfix list:
>vim
    :copen
    :120,140Csub      " or visually select rows and press : then Csub
    " edit those 21 entries; the rest round-trip unchanged
    :w
<

Close several buffers at once (uses "buffers" mode; the picker must populate
the quickfix list with a recognisable title):
>vim
    :Csub
    " delete lines for buffers to close, then:
    :w
<

==============================================================================
COMMANDS                                                        *csub-commands*

:[range]Csub                                                       *:Csub*
    Open the current quickfix or location list in an editable buffer using
    the list window. Without a range, the entire list is shown. With a
    range (e.g. `:5,10Csub` or `:'<,'>Csub`), only the entries in that
    range are shown; entries outside the range round-trip unchanged when
    you write. Re-invoking `:Csub` while inside the csub buffer toggles
    back to the list window without discarding edits.

==============================================================================
SCOPED EDITING                                                     *csub-scope*

When `:Csub` is invoked with a range from a quickfix or loclist window,
only the selected slice is loaded into the csub buffer. On write:

- Edits and deletions inside the slice are applied to those entries.
- Entries outside the slice are spliced back unchanged.
- The list id and title are preserved.
- If you delete every entry in the slice, the scope collapses and the
  next `:Csub` (no range) shows the full list again.

Invoking `:Csub` with a different range (or without a range) on the same
list while you have unsaved edits is treated as a context switch; csub
warns and aborts. Finish or discard the existing edits first.

A ranged `:Csub` from a non-list window is rejected — the visual range
must be over a list buffer.

==============================================================================
OPTIONS                                                          *csub-options*

                                                                *csub-handlers*
handlers ~
    List of handler tables to detect mode based on list title. Each handler
    has two fields:
    - `match`: String to match against the list title (plain text)
    - `mode`: Mode to use when matched ("replace", "buffers", or nil)

    Handlers are checked in order; the first match wins. The same handler
    list applies to both quickfix and location lists.

                                                            *csub-default_mode*
default_mode ~
    Fallback mode when no handler matches. Default: nil (csub disabled for
    unmatched lists). Set to "replace" or "buffers" to enable csub on every
    list that no handler claims.

                                                                  *csub-modes*
MODES ~

csub supports different modes that change behavior on save:

"replace"                                                  *csub-mode-replace*
    - Delete line: Remove entry from the list
    - Edit text: Replace the line in the source file
    - Use case: grep results, compiler errors, diagnostics

"buffers"                                                  *csub-mode-buffers*
    - Delete line: Close the buffer (`:bdelete`) and remove from the list
    - Edit text: Ignored (no changes applied)
    - Use case: Buffer pickers that populate quickfix or loclist
    - Use `:w!` to force-close modified buffers

nil                                                       *csub-mode-disabled*
    - Disables csub for matching lists
    - `:Csub` will show a message and do nothing

g:csub_no_save                                                *g:csub_no_save*
    When set to a non-zero value and 'hidden' is enabled, avoid saving
    buffers while applying changes (leave buffers modified but listed).
    Defaults to 0.

==============================================================================
HIGHLIGHT GROUPS                                              *csub-highlights*

All groups are defined with `default = true` so user overrides take effect.

`CsubMetaFileName`   linked to `Comment`    — file-name part of the metadata
`CsubMetaNumber`     linked to `Number`     — line/column numbers
`CsubSeparator`      linked to `Comment`    — `|` separators in the metadata
`CsubDirtyLine`      linked to `DiffChange` — `~` sign on edited rows

==============================================================================
NOTES                                                              *csub-notes*

- The buffer uses `filetype=csub` and is named `[csub]`. A single shared
  csub buffer is reused across invocations; switching to a different list
  with unsaved edits triggers a warning.
- The metadata column is virtual text; wrapping is disabled locally.
- Edited rows are marked with a `~` sign in the sign column (`signcolumn`
  auto-shows). The mark disappears when the line is reverted to its
  original text.
- Original text changes in target files are detected; if the current
  buffer differs from the original entry text and from your edits, an
  error is reported and that entry is left unchanged.
- Mode is detected from the list title when `:Csub` is invoked.
- In "buffers" mode, only line deletions have an effect; text edits are
  ignored.
- Location lists are addressed by their owner window (the window the
  loclist is attached to), which survives the loclist display window
  being closed.
